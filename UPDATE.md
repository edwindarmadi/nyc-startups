# Refreshing the NYC Startup Index

Live site: see README.md. Everything is static: `public/` is served as-is by Vercel, and the site reads
`/data/startups.json`, `/data/news.json` and `/data/jobs.json` at runtime. The home page (`#/`) is the jobs board;
news lives at `#/news`, companies at `#/companies`.

## Where data lives

| Path | What |
|---|---|
| `data/startups.json` | **Canonical** company list (generated). Do not hand-edit — edit the manual files below and rebuild. |
| `data/news.json` | **Canonical** news feed (generated from funding/acquisition data + `data/manual/news.json`). |
| `data/manual/supplemental.json` | Hand-researched companies not on startups.gallery (focus-area additions). |
| `data/manual/news.json` | Hand-added news items (launches, hires, other). Optional; create it as a JSON array. |
| `data/manual/tags.json` | Focus-tag membership by company id: `climate`, `fair_finance`, `civic`, `ai_everyday`. |
| `data/manual/exclude.json` | Company ids to exclude + reason (e.g. not NYC-based). |
| `data/manual/linkedin_ignore.json` | Ids whose LinkedIn link points at the wrong company (ignore LinkedIn data for them). |
| `data/manual/url_fixes.json` | `{dead_url: replacement_url or null}` — applied by `build_data.py` to every source, careers, funding and news URL. Use this to *fix* dead links (the dead-link report only covers the last check, so pruned links would otherwise come back on the next rebuild). |
| `data/manual/overrides.json` | Optional `{id: {field: value}}` patches applied last (e.g. fix a description). |
| `data/jobs.json` | **Canonical** open-roles list (generated by `scripts/fetch-jobs`, rebuilt from scratch each run). |
| `data/jobs-coverage.json` | Generated: per company, which job feed was used (`api` + ats/slug), `no_feed`, or `feed_error` + the error. |
| `data/manual/ats.json` | Force a job feed per company id: `["ashby","slug"]`, or `null` to skip a wrong/foreign board. |
| `data/dropped.json` | Generated: every company dropped and why (mostly non-NYC HQ per LinkedIn). |
| `data/link-report.json` | Generated by `scripts/check-links`. |
| `public/data/*.json` | Copies of the canonical files that get deployed (written by `build_data.py`). |
| `raw/` | Git-ignored cache of fetched HTML (startups.gallery pages, homepages, LinkedIn pages). |
| Persistent copy | `/cursor/stores/store-35610ab0-580f-435b-810f-c5831505efc3/nyc-startups/` (data + manual files + scripts). |

## Rules (non-negotiable)

- **Never invent** a stage, amount, date or headcount. If no source you actually saw backs it, write `"unknown"` (or `null` date in manual files).
- Every company needs ≥1 real source URL (site, LinkedIn, or funding announcement).
- **NYC only** (all five boroughs). HQ is checked against the LinkedIn "Headquarters" field. If LinkedIn says elsewhere
  (incl. NY State towns like Mount Kisco) the build drops it automatically. If there's no LinkedIn data, a manual entry
  needs `hq_hint` + `hq_hint_url` (a press source saying "Brooklyn-based" etc.), otherwise it's dropped.
- Stage enum: `pre-seed, seed, Series A, Series B, Series C+, public, acquired, unknown`.
- `round` (what the site filters on, URL param `round=`) is derived in `build_data.py` (`round_of`) from the sourced round name:
  `pre-seed, seed, Series A, Series B, Series C, Series D, Series E+ (E/F/G/H…), Series C+ (unspecified), public, acquired, unknown`.
  A letter is assigned only if the source names it (`round_name` keeps the exact name, e.g. "Series H"). A late-stage round with no
  letter goes to `Series C+ (unspecified)`; "Venture"/debt/undisclosed-type rounds go to `unknown`. News items get `round` the same way
  from their headline. Shareable URLs: `#/companies?round=Series%20A&round=seed&focus=climate`, `#/?round=Series%20B`.

## Full refresh (recurring run)

```bash
cd /workspace/nyc-startups          # or clone github.com/edwindarmadi/nyc-startups
# if raw/ is missing (fresh clone) this rebuilds it from scratch; takes ~10-15 min (LinkedIn is throttled on purpose)
scripts/fetch_sources.sh            # add --force to re-download everything, --skip-linkedin for a fast pass
python3 scripts/build_data.py       # writes data/*.json and public/data/*.json, prints counts
scripts/check-links                 # dead-link check (see below)
python3 scripts/build_data.py       # rebuild again so dead URLs from the report are pruned
```

Then review: `git diff --stat data/`, open `data/dropped.json` for newly dropped companies, spot-check a few new entries.
LinkedIn sometimes returns HTTP 999 (rate limit); just re-run `scripts/fetch_sources.sh` later — it only refetches missing pages.

## Jobs refresh (run with every refresh, or on its own daily/weekly)

```bash
scripts/fetch-jobs                    # ~1 min; all companies, 12 parallel workers
scripts/fetch-jobs --only rain-xyz,lithic   # just these (others kept from the last run)
scripts/fetch-jobs --refetch-careers  # also re-download careers pages to re-detect boards (after adding companies)
```

What it does:
1. **Detects each company's ATS** from `careers_url`, the job links on its startups.gallery page (`raw/co/`), and its
   careers / `/careers` / `/jobs` page HTML (`raw/careers/`). The last working feed in `data/jobs-coverage.json` is
   always retried too, so a fresh clone without `raw/` still works. `data/manual/ats.json` overrides detection.
2. **Fetches public JSON feeds only** (no auth, no scraping of free-form pages):
   Ashby `api.ashbyhq.com/posting-api/job-board/<slug>`, Greenhouse `boards-api.greenhouse.io/v1/boards/<slug>/jobs`,
   Lever `api.lever.co/v0/postings/<slug>`, Workable `apply.workable.com/api/v1/widget/accounts/<slug>`,
   Gem `api.gem.com/job_board/v0/<slug>/job_posts/`, Rippling `ats.rippling.com/api/v2/board/<slug>/jobs`,
   SmartRecruiters `api.smartrecruiters.com/v1/companies/<slug>/postings`.
3. **Rebuilds `data/jobs.json` from scratch** — roles no longer in a feed disappear (the summary prints
   "dropped since last run"). `first_seen` is carried over for roles that stay.
4. Derives, per job: `department_group` (Data/Analytics, Engineering, Product, Design, Sales, Ops, Finance,
   Compliance/Risk/Legal, Marketing, Other — from the posting's department/team, then the title),
   `location_classes` (NYC / Remote / Hybrid / Other, a job can have several), `seniority` from the title
   (Intern/Entry, Mid, Senior, Lead/Manager+), and `fits_edwin` (data/analytics, business/ops analyst & strategy-ops,
   compliance / risk / AML / KYC / BSA / fraud roles; engineering, counsel and sales excluded). Tune `DEPT_RULES`, `FIT` and the
   seniority/fit functions in the script.
5. Writes the compact site copy `public/data/jobs.json` directly — no `build_data.py` run is needed for jobs alone.

Checks after a run:
- Skim the summary; a big drop in jobs usually means a feed moved (look at `feed_error` entries in `data/jobs-coverage.json`).
- When a company switches ATS or the detected board belongs to a different company, pin it in `data/manual/ats.json`
  (e.g. `"echo": ["ashby", "echo.ai"]`) or set it to `null`.
- `no_feed` companies (Comeet, Dover, Notion, Wellfound, LinkedIn-only careers pages…) show the startups.gallery
  role snapshot on their company page instead, clearly labelled.
- Then commit `data/jobs.json data/jobs-coverage.json public/data/jobs.json` and push (Vercel auto-deploys).

## Adding a company by hand

Append to `data/manual/supplemental.json`:

```json
{"id":"slug","name":"Name","website":"https://…","description":"One line on what it does.",
 "sectors":["Climate"],"stage":"seed",
 "last_round":{"amount":"$3.6M Seed","date":"2023-07-24","url":"https://source-of-the-round"},
 "hq_hint":"Brooklyn, NY (TechCrunch: 'Brooklyn-based …')","hq_hint_url":"https://…",
 "linkedin":"https://www.linkedin.com/company/slug","careers_url":null,"focus":["climate"]}
```

`date` may be `null` when the source doesn't give one. Unknown amount → `"unknown"`. Then fetch its LinkedIn page
(`scripts/fetch_sources.sh --skip-linkedin` won't; run the full script, or
`curl -sL -A "Mozilla/5.0" https://www.linkedin.com/company/slug -o raw/li/<id>.html`) and rebuild. A supplemental entry with a
dated `last_round.url` automatically becomes a news item (acquired → acquisition, public → other).

Focus tags for startups.gallery companies: add the id to the right list in `data/manual/tags.json`.

## Adding news

Funding rounds/acquisitions from startups.gallery pages become news automatically. For anything else, add to
`data/manual/news.json` (array):

```json
{"id":"companyid-launch-2026-10-21","date":"2026-10-21","startup_id":"companyid","type":"launch",
 "headline":"X launches Y","summary":"One line.","source_url":"https://real-source"}
```

`type` ∈ `funding | launch | acquisition | other`. `startup_id` must exist in startups.json (otherwise the item is dropped).
Only real items with a real source URL.

## Dead-link check

```bash
scripts/check-links [--workers 16] [--timeout 20] [--only-dead]
```

Checks every website, careers, source, HQ-source and news URL (HEAD, falls back to GET). Writes `data/link-report.json`
with `dead` (404/410/DNS failure), `errors` (timeouts/5xx — recheck), `blocked` (401/403/429/999 bot walls — not proof of death).
Exit code 1 if anything is dead. `build_data.py` reads the report and automatically removes dead URLs (dead careers link →
null; dead funding link → falls back to the startups.gallery profile). To properly *fix* a dead link, find the new URL and put it in
`data/manual/url_fixes.json` (or `overrides.json` / the manual file), then rebuild.

## Redeploy

The Vercel project is `nyc-startups` (static, output dir `public/`, no build step).

- **Git** (if the project is linked to the GitHub repo): commit + push to `main`; Vercel deploys automatically.
  ```bash
  git add -A && git commit -m "Data refresh $(date +%F)" && git push
  ```
- **Vercel CLI** (needs a token): `vercel deploy --prod --yes --token "$VERCEL_TOKEN"` from the repo root.
- **Vercel connector / MCP**: `create_deployment` for project `nyc-startups`, target `production`, uploading the files in `public/`.

Verify after deploy:
```bash
curl -s https://<prod-url>/data/startups.json | python3 -c "import json,sys;d=json.load(sys.stdin);print(d['meta'])"
curl -sI https://<prod-url>/ | head -1    # must be 200, not 401 (deployment protection must stay off for production)
```

Finally copy the data to the persistent store:
```bash
S=/cursor/stores/store-35610ab0-580f-435b-810f-c5831505efc3/nyc-startups
mkdir -p $S && cp -r data scripts UPDATE.md README.md $S/
```
